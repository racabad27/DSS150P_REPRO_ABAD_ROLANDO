# Phase I — Baseline capture and engineering gaps

Before changing anything I went back to what our Predictive Analytics project
*actually did*, cell by cell, so I know exactly what I have to reproduce. The
inputs for this step were the two Colab notebooks
(`EDA_PredictiveProject_FINAL.ipynb`, `Cleaning&FeatureEngineering_PredictiveProject_FINAL.ipynb`),
the dataset copy inside the project zip, the standalone Kaggle CSV, and the paper.

> **Attribution.** The dataset, problem statement, feature definitions, model
> choices and reported metrics come from our group project
> (Risma, V. L. S.; Abad, R. A.; Toliba, M. G.). The data engineering in this
> repository (ingestion, layers, storage, orchestration, tests, documentation)
> is my individual work for DSS150P.

## 1. The old project as a lifecycle

| Lifecycle stage | What the old project did | Where |
|---|---|---|
| Generation | IIoT readings every 15 minutes (one row per slot, factory assigned per row), 1 Jan 2021 – 8 Nov 2023, 100,000 rows | Kaggle dataset |
| Ingestion | CSV uploaded by hand into a Colab session, read with `pd.read_csv('industrial_fire_risk_data.csv')` | both notebooks, first cells |
| Storage | Only the Colab session disk. `cleaned_...csv` and `final_cleaned_...csv` were written but never kept or versioned | cleaning notebook cells 5, 28 |
| Transformation | Drop rows with missing `Workers`; parse `Date`+`Time`; temporal features; binary maps; one-hot; 3 interaction terms; drop `Accident` | cleaning notebook cells 3–13 |
| Training | Linear Regression, Random Forest (100 trees, seed 42), XGBoost (100 trees, seed 42), first 80 % of rows train / last 20 % test | cells 17–22 |
| Evaluation | MSE / RMSE / MAE / R² printed with 2 decimals; 5-fold `TimeSeriesSplit`; feature importance | cells 17–32 |
| Outputs / consumers | Numbers copied by hand into the paper tables. No saved model, no predictions file, no machine-readable metrics | paper |

## 2. Parts that were manual, hidden, non-deterministic or machine-specific

1. **Manual upload, no identity check.** Every Colab session started with a
   hand upload. Nothing recorded *which* file was used.
2. **The notebook ran on an Excel re-saved copy.** The CSV inside the project
   zip has dates like `08/11/2023` and times like `0:00:00` (SHA-256
   `6457d041…4b44536`), while the Kaggle file uses `2023-11-08` and `00:00:00`
   (SHA-256 `5db607c5…14f309ba`). I compared both cell by cell: all 100,000
   records are identical, only the text formatting differs. The notebook
   hard-codes `format="%d/%m/%Y %H:%M:%S"`, so it **crashes on the original
   Kaggle file**. The EDA notebook even printed the failed `YYYY-MM-DD` check,
   while the paper (Section 3.2) says both columns parsed cleanly.
3. **Hidden notebook state.** `df` is overwritten and mutated in place across
   cells (`sample` → `df`, `inplace=True` drops). Running cells out of order
   gives different results.
4. **No library versions recorded.** This turned out to matter: the paper's
   XGBoost row (MSE 10.57) and the notebook's saved output (MSE 10.52) come
   from *different XGBoost versions* (≤ 3.2.0 vs ≥ 3.3.0). Colab upgraded the
   library between the two runs. scikit-learn 1.9 also changes Random Forest
   results. Details in [`evidence/dependency_sweep.md`](evidence/dependency_sweep.md).
5. **Split depends on implicit row order.** `X.iloc[:split_point]` is only a
   time split because the file happens to be sorted by time. Nothing checked it.
6. **Metrics copied by hand.** Only 2-decimal printouts existed, so the paper
   was filled in manually. Table 3 ended up mixing two runs (its XGBoost fold
   R² values match one XGBoost version and its averages match the other).
7. **No data validation.** Missing values were dropped silently; no range,
   category, duplicate or schema checks existed.
8. **Repeated work.** Cross-validation called `cross_val_score` three times
   per model (once per metric), so every model was trained 15 times instead of 5.

## 3. Baseline record

The machine-readable version is [`metadata/expected_metrics.json`](../metadata/expected_metrics.json),
generated by [`scripts/capture_baseline.py`](../scripts/capture_baseline.py)
(every number in the script says which table or notebook cell it came from).

| Item | Baseline |
|---|---|
| Task / target | Regression on `Risk` (0–100 score) |
| Rows | 100,000 in source → 98,000 after dropping missing `Workers` |
| Features | 26, in the notebook order (temporal, binary maps, one-hot with `drop_first`, 3 interactions); `Accident` excluded |
| Split | Chronological: first 78,400 rows train (2021-01-01 00:00 → 2023-04-14 05:00), last 19,600 test (2023-04-14 05:15 → 2023-11-08 15:45) |
| Seeds | `random_state=42` for Random Forest and XGBoost |
| Hyperparameters | LinearRegression defaults; RandomForestRegressor `n_estimators=100`; XGBRegressor `n_estimators=100` |
| Preprocessing | No scaling; encodings computed on the full data (fixed categories, so no leakage) |
| Cross-validation | `TimeSeriesSplit(n_splits=5)` over all 98,000 rows |

**Reported test metrics (paper Table 2 — baseline of record):**

| Model | MSE | RMSE | MAE | R² |
|---|---|---|---|---|
| Linear Regression | 11.92 | 3.45 | 2.75 | 0.95 |
| Random Forest | 10.47 | **3.24** | 2.57 | 0.96 |
| XGBoost | 10.57 | 3.25 | 2.59 | 0.96 |

**Primary metric:** Random Forest RMSE on the chronological test set (3.24).

**Tolerance rule:** a reproduced value must agree with the reported value at
the precision it was reported — `|reproduced − baseline| ≤ 0.005` for
2-decimal values and `≤ 0.0005` for values printed with 3 or more decimals.
That is stricter than the lab's suggested ±0.01. The baseline file contains
156 individual checks: 114 are blocking, and 42 XGBoost checks that belong to
the *other* XGBoost version are reported as documented, accepted deviations.

## 4. Engineering-gap table

| # | Current behaviour | Risk | DSS150P concept | Remediation in this repo |
|---|---|---|---|---|
| 1 | CSV uploaded by hand, read from the working directory | Cannot prove which file was used; only runs inside that session | W2 source systems, W4 reproducible environments | Immutable `data/source/`, SHA-256 in `source_manifest.yml`, checked before every run |
| 2 | Spreadsheet re-save changed the date format; notebook hard-codes `%d/%m/%Y` | Format drift breaks parsing or silently swaps day and month | W2 schemas and data contracts | `data_contract.yml` declares formats; raw keeps text; staging parses with the contract format and quarantines failures |
| 3 | Notebook cells mutate shared state | Hidden state, results depend on execution order | W4 modular code | Pure functions in `src/`, one CLI entry point, Airflow DAG |
| 4 | No pinned versions | Metrics drift between runs (already happened with XGBoost) | W4 dependency pinning | Exact pins in `requirements.txt`, Docker images, `env-check` |
| 5 | Split relies on file order | Different rows in train/test if the file is ever re-sorted | W5 deterministic transformations | Explicit ordering by `reading_ts`; `split_manifest.json` with row-key hashes |
| 6 | Metrics only printed, copied into the paper by hand | Transcription mistakes (Table 3) | W9 delivery and operations | `outputs/metrics.json` compared automatically with `expected_metrics.json` |
| 7 | Cleaning mixed with modelling in one notebook | Logic is duplicated and untestable | W5 ETL layers | raw → staging → curated layers; exclusions are logged |
| 8 | No data-quality checks | Bad rows reach the model unnoticed | W8 quality and testing | `validate.py` checks, quarantine, failure thresholds, tests |
| 9 | Nothing stored beyond the session | No lineage, no reuse | W6 storage | Parquet layers and PostgreSQL tables with audit columns |
| 10 | No orchestration or retries | Manual reruns, partial runs go unnoticed | W7 orchestration | Airflow DAG with dependencies, retries, timeouts and parameters |
| 11 | No logs or run history | Failures cannot be explained afterwards | W8 observability | JSON logs, per-run records, audit tables |
| 12 | Only the seeds of the models were fixed | Hard to prove two runs are the same | W10 end-to-end reproducibility | All seeds in config, fold boundaries and data fingerprints recorded |
